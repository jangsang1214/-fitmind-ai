# GARANG UI 복구 및 코드 오류 점검 — 2026-09-01

## 기준과 배포 오류

GitHub main `0e8e4ab324f7914f3eb6e3b400ee5b4316b5e595`를 조사했다. 전체 137개 항목이 루트 파일이고 하위 폴더가 없었다. index.html은 기존 전달본과 같은 폴더 경로를 참조한다. 20개의 고유 로컬 참조 파일이 해당 경로에 없어 CSS, 앱 JavaScript, 설정, 이미지가 로드되지 않는다. 실제 GitHub Pages에서 흰 배경, 기본 글꼴, 깨진 로고, 동작하지 않는 로그인/데모 UI를 재현했다.

기존 V10.9.1 기반 1차 업데이트 소스의 디렉터리 구조를 복원한다. 기존 원격 루트 파일은 제거하지 않는다. 이름이 중복되는 legacy 파일도 보존하되 index.html의 실행 경로에는 연결하지 않는다. 앞으로 ZIP 안의 파일을 개별 선택해 루트에 올리지 말고 폴더 구조를 유지한 Git 작업으로 반영해야 한다.

## 검증

- 기존 core 테스트 15개, adapter/repository 테스트 8개, 새 오류 회귀 테스트 13개: 총 36개 PASS.
- 모든 72개 JS/CJS 구문 검사, 21개 JSON/manifest, 6개 JSONL 파싱, 32개 활성 참조 검사 PASS.
- 수정본 로컬 브라우저에서 13개 경로 열기와 각 화면 제목 확인: 모두 렌더링 실패 fallback 없음.
- Planner 추가·새로고침·완료·수정·삭제, 로컬 AI 응답을 브라우저에서 조작했다.
- 클라우드 계정 전환, 비동기 순서, 저장 실패는 제어된 단위 테스트로 재현했다. 실제 Firebase 계정/운영 DB 통합시험으로 간주하지 않는다.
- 이번 검사는 UI 전체의 픽셀 품질이나 실제 iPhone Safari 검증을 대체하지 않는다. 이전 52개 너비 검사는 이번 수정본의 재검증 결과로 재사용하지 않는다.

## 남은 위험과 별도 작업

1. 실제 Firebase Authentication/Firestore 규칙 배포·권한, 두 계정과 두 기기의 동시 수정 검증 필요. 쓰기 큐는 한 탭의 순서만 보호한다. 다중 기기 충돌 병합·서버 버전 조건은 미구현이다.
2. 운영 LLM/OCR/결제 endpoint 미연결. 실제 결제/구독 권한은 서버 발급 및 검증을 구현해야 한다. 로컬 PRO 필드를 유료 접근 권한의 근거로 사용하면 안 된다.
3. 현재 Firestore 규칙에서 사용자 자신의 문서는 쓰기 가능하다. 클라이언트가 설정하는 plan은 서버 entitlement가 아니며, 규칙 파일이 실제 운영에 배포됐는지 이번에는 검증하지 않았다.
4. 실제 iPhone 키보드·날짜/시간 입력·카메라·백그라운드 GPS·영상 합성·공유·PWA 업데이트 검증 필요. 로컬 타이머 알림은 실제 서버 Push가 아니다.
5. 원본 legacy 모듈은 전체 구문 검사만 수행했고 현재 엔트리에 연결되지 않은 동작까지 안전하다고 보장하지 않는다. 추후 임의로 다시 연결하지 말 것.
6. 모든 오류가 제거됐다는 보증은 아니다. 확인된 결함을 수정한 복구 후보이며 main 반영/배포 전까지 운영 사이트는 바뀌지 않는다.

판정: 코드·경로 복구 검증 통과 / 운영 배포와 실제 기기·서버 검증 대기.
